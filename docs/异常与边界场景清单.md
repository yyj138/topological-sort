## 场景清单

### 场景 1：非法输入 — 缺少左括号

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `a,b>` 这样缺少 `<` 的行 |
| **程序应表现** | 弹窗提示："第X行：缺少左括号 '<'，当前内容为: a,b>" |
| **处理方案** | `InputValidator` 校验阶段拦截，不进入解析流程；输入框中该行标红高亮 |

---

### 场景 2：非法输入 — 缺少右括号

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `<a,b` 这样缺少 `>` 的行 |
| **程序应表现** | 弹窗提示："第X行：缺少右括号 '>'，当前内容为: <a,b" |
| **处理方案** | `InputValidator` 校验阶段拦截，不进入解析流程；输入框中该行标红高亮 |

---

### 场景 3：非法输入 — 缺少逗号

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `<a b>` 或 `<ab>` 这样缺少逗号的行 |
| **程序应表现** | 弹窗提示："第X行：缺少逗号 ','，当前内容为: <a b>" |
| **处理方案** | `InputValidator` 校验阶段拦截，不进入解析流程；输入框中该行标红高亮 |

---

### 场景 4：乱码行

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `###乱码内容@@@` 或其他无法识别为 `<a,b>` 格式的文本行 |
| **程序应表现** | 弹窗提示："第X行：缺少左括号 '<'，当前内容为: ###乱码内容@@@" |
| **处理方案** | `InputValidator` 校验阶段拦截；如果是纯乱码（不含 `<`），报缺少左括号错误 |

---

### 场景 5：重复边

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入了两条或多条相同的边，如 `<a,b>` 出现两次 |
| **程序应表现** | 第一条正常解析；第二条产生警告"重复的关系 <a,b>，已忽略"；图中只保留一条边，入度不重复增加 |
| **处理方案** | DataParser 解析时使用 seenEdges 集合检测重复，重复边记入 warnings 列表（不是 errors）；Graph.addEdge 返回 false 表示重复；B 的状态栏可选择性显示警告数 |

---

### 场景 6：自环（顶点指向自身）

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `<a,a>` 这样的自环边 |
| **程序应表现** | 正常解析并加入图，不报错也不产生警告；环检测模块返回环路径 `[a, a]`；B 弹窗提示"检测到环路: a → a"；C 的绘图高亮自环边 |
| **处理方案** | DataParser 不拦截自环，直接调用 Graph.addEdge 保留；Graph 正常记录自环（入度 +1，出度 +1）；拓扑排序算法不能忽略自环，Kahn 算法因入度 > 0 无法消除自环节点，最终检测到环 |

---

### 场景 7：含环图（存在循环依赖）

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入的关系构成循环，如 `<a,b>` `<b,c>` `<c,a>` |
| **程序应表现** | 弹窗提示："检测到环路: a → b → c → a，无法完成拓扑排序"；关系图中环路径上的边和节点红色高亮 |
| **处理方案** | `CycleDetector` 使用 Kahn 计数法（出队数 < 顶点数）判定有环；DFS 三色标记定位具体环路径；结果面板清空或显示"含环，无有效拓扑序列" |

---

### 场景 8：空数据（无任何输入）

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户点击"计算"按钮时输入框为空 |
| **程序应表现** | B 的 UI 层检测到空图后弹出提示"没有有效数据，请输入至少一条关系"；不启动算法计算 |
| **处理方案** | 空输入由 UI 层（B）判断并提示，不由 InputValidator 或 DataParser 报错；DataParser 对 null/空输入返回空结果（无错误） |

---

### 场景 9：全部孤立节点（无边）

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入的顶点之间没有任何先修关系，或输入为空图 |
| **程序应表现** | 弹窗提示："没有有效的数据行，请输入至少一条关系数据"；或正常显示所有节点（无边连接） |
| **处理方案** | `DataParser` 检测到无有效边时返回错误；`Kahn 算法`对空图或全孤立点图应返回所有顶点的任意排列 |

---

### 场景 10：大图（千节点规模）

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户导入包含 1000 个节点以上的大规模数据文件 |
| **程序应表现** | 计算在设定上限内完成（默认输出前 1000 条拓扑序列）；状态栏显示总结果数和计算耗时；界面不卡死 |
| **处理方案** | `AllTopoSorts` 设置 `maxResults` 上限（默认 1000），防止结果爆炸；分页显示结果（每页 20 条）；绘图使用性能优化的布局算法 |

---

### 场景 11：超长结果（拓扑序列数量极大）

| 项目 | 内容 |
|---|---|
| **触发条件** | 输入数据的拓扑排序结果数量远超 1000 条（如全孤立节点图，n 个节点有 n! 种排列） |
| **程序应表现** | 默认只输出前 1000 条，状态栏显示"共 XXXXX 条（显示前 1000 条）"；用户可切换"全部"模式 |
| **处理方案** | `AllTopoSorts` 的 `maxResults` 参数控制上限（0 表示全部，1000 为默认）；切换"全部"前弹窗警告"结果数量巨大，可能需要较长时间" |

---

### 场景 12：注释行和空行混合

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入中包含 `#` 开头的注释行和空行 |
| **程序应表现** | 静默跳过注释行和空行，不报错；正常解析有效数据 |
| **处理方案** | `DataParser` 跳过 `#` 开头行和空行；`InputValidator` 同样跳过；不影响解析结果 |

---

### 场景 13：全角尖括号输入

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户使用中文输入法输入了全角尖括号 `＜a,b＞` |
| **程序应表现** | 静默转换为半角 `<a,b>` 后正常解析，不报错 |
| **处理方案** | `DataParser` 和 `InputValidator` 在预处理阶段将 `＜` 转为 `<`、`＞` 转为 `>` |

---

### 场景 14：行首尾多余空格

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `  <a,b>  ` 这样带前后空格的行 |
| **程序应表现** | 静默去除首尾空格后正常解析，不报错 |
| **处理方案** | `DataParser` 对每行执行 `trim()` 后再解析 |

---

### 场景 15：文件不存在或路径为空

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户点击"打开文件"后取消选择，或指定的文件路径不存在 |
| **程序应表现** | 弹窗提示："未选择文件，请选择一个文件后再试" 或 "文件不存在：XXX" |
| **处理方案** | `FileManager` 在读取前检查文件是否为 null 和是否存在，抛出中文 `IOException` |

---

### 场景 16：括号内容为空

| 项目 | 内容 |
|---|---|
| **触发条件** | 用户输入 `<,>` 或 `<>` 这样括号内没有顶点名称的行 |
| **程序应表现** | 弹窗提示："第X行：逗号前的顶点名称为空" 或 "第X行：括号内为空" |
| **处理方案** | `InputValidator` 和 `DataParser` 检查逗号分割后的两部分是否为空 |
