## 一、枚举默认上限：1000 条还是 10000 条

| 比对位置 | 当前内容 |
| --- | --- |
| A：`docs/接口契约.md` §4，第 75 行 | `maxResults` 默认由调用方传入 **1000**；`0` 表示不限数量；超时默认值由 B 配置 |
| B：`docs/需求分析报告.md` §3.2，第 137 行 | B 调用配置上限 **10000** 条、超时 **30 秒** |
| B：同一需求报告附录 Q-2，第 449 行 | 默认上限 **1000** 条，可切换全部 |
| B：`src/ui/MainController.java` | `MAX_RESULTS = 10000`，`TIMEOUT_MILLIS = 30_000L` |

问题在于默认配置没有统一，而且 B 的需求报告内部也有两个值。A 的算法通过参数接收数量限制，1000、10000 和 0 都支持，不需要为此更改算法签名。30 秒是 B 可以选择的调用配置，与 A 的接口契约并不冲突。

**建议统一方式：优先沿用已确认契约，默认 1000 条，超时 30 秒。**B 将 GUI 默认常量和需求 §3.2 同步为 1000，并核对 GUI 详细设计中的常量、时序图与流程说明。若确实希望默认 10000，则由 A、B 确认后，A 更新契约及相关设计说明，B 更新附录 Q-2，避免只改其中一处。

“可切换全部”还需要与实际界面一致：若已有切换功能，无数量上限时传入 0，但仍可保留 30 秒时限；若尚未实现，则应注明待实现，不能写成已有能力。不论上限选多少，界面及导出都应区分“已生成数量”和“确切总数”。只有 `isComplete() == true` 时才能声明结果已全部生成。

**请 B 确认：**是否采用默认 1000 条、30 秒；当前是否确有“全部”切换入口。若选择默认 10000，请说明最终配置，A 将同步契约与报告。

## 三、自环措辞：保留自环并拒绝完整排序，不能忽略自环

| 比对位置 | 当前内容 |
| --- | --- |
| A：`docs/接口契约.md` §2，第 38 行；§6，第 110、121 行 | 自环作为真实关系保留，统一通过环检测报告，不删除自环来获得无环图 |
| B：需求报告 §5.1 第 8 条，第 213 行 | “自环 `<a,a>` 被识别并标记，不参与拓扑排序。” |

B 的文字可能表示“检测到自环后，整张图不再排序”，也可能被读成“忽略这条边，其他内容照常排序”，因此需要明确含义。按 A 的实现，自环保留在 Graph 中，对该节点入度和出度各贡献 1，环路径可返回 `[a,a]`。由于 a 不可能严格先于自身，含自环的整张图不存在合法完整拓扑序列；这项差异是措辞歧义，不能据此直接断定 B 的代码忽略了自环。

**建议将 B 的原句替换为：**“自环 `<a,a>` 保留在图中并作为环报告；含自环的输入图不存在合法的完整拓扑序列，界面提示并高亮自环，不得通过忽略自环继续生成完整排序结果。”该表述与现有 A 契约一致，不需要更改算法接口。联调时可输入 `<A,A>` 和 `<B,C>`，检查自环保留、显示含环，并且不会把 `[B,C]` 展示为整张图的完整拓扑序列。

**请 B 确认：**是否采用上述替换文字，并在 GUI 联调中按该行为检查。A 提供环路径，B 组织提示，C 根据闭合路径高亮对应节点和边。
