# 跨模块接口契约

本契约为 V1.0 正式版，由 A 编写，已于 2026 年 9 月 17 日经团队会议确认，作为各模块开发、调用和测试的共同依据。B 的界面、C 的绘图、D 的解析、A 的图模型与算法、E 的测试均遵循本文约定。文档规定接口及行为，代码完成情况和测试结果分别由实际源码与验证记录说明。

## 一 职责和调用顺序

| 模块 | 提供者 | 输入与输出 |
| --- | --- | --- |
| Graph | A | 存储课程及有向关系，提供只读遍历 |
| TopologicalSolver | A | 图输入，返回一种完整拓扑序列或含环状态 |
| AllTopoSorts | A | 图和计算限制输入，返回若干序列、完整性与停止原因 |
| CycleDetector | A | 图输入，返回具体闭合环路径；无环返回空列表 |
| DataParser | D | 解析文本并建立 Graph，返回图、错误和警告 |
| InputValidator | D | 检查输入格式，与 DataParser 使用一致的校验规则 |
| GraphPanel | C | 接收图和高亮节点，负责布局、绘图与图片输出 |
| MainController | B | 组织数据校验、绘图和后台计算，将返回状态展示给用户 |
| AlgorithmRunner 与测试 | E | 调用相同解析和算法接口，完成无界面联调与独立验证 |

界面先校验和解析输入，再显示关系图，判环后才执行多结果枚举。B 负责后台任务及界面线程更新，A 的算法负责定期检查取消和超时，不从算法内部弹出窗口。计算期间必须保证输入图稳定：可使用独立图快照，也可禁止修改正在计算的同一实例，由 B 的调用流程落实并与 C 的编辑操作保持一致。

## 二 图结构

节点以去除首尾空白后的名称作为唯一标识，区分大小写，例如 A 和 a 是不同节点。关系 `<a,b>` 表示 a 必须先于 b，对应 a 指向 b。名称允许中文和内部空格，例如 `MA 141` 和 `CS 225` 均为合法的完整名称；格式分隔符、换行和空名称不作为合法名称。D 的解析与输入校验、A 的 Graph 名称处理均遵循这一规则，不删除或拆分课程名称中的内部空格。

```java
// model.Graph 的实例方法
boolean addVertex(String name);
boolean addEdge(String from, String to);
boolean removeEdge(String from, String to);
List<String> getVertexNames();
List<String> getSuccessors(String name);
int getInDegree(String name);
int getOutDegree(String name);
int getVertexCount();
int getEdgeCount();
```

`addEdge` 自动补齐两端节点，新边返回 true，重复边返回 false 且不重复增加入度。自环保留为一条边，由环检测报告，不通过忽略自环把错误数据变成无环图。查询未知节点时抛出带明确信息的参数异常，B 或 E 在调用边界转换为提示或测试失败。

返回的节点和后继列表采用只读视图或独立副本，调用者不能通过返回列表修改 Graph 的内部关系。契约不保证图变更后旧列表自动刷新，调用者需要最新数据时重新查询；节点和后继按录入顺序稳定遍历。算法计算使用局部入度副本，不改变 Graph 的原始入度；`Vertex` 和 `Edge` 按图数据结构设计实现，绘图不依赖它们的可变内部字段。

## 三 单序列排序

```java
// algorithm.TopologicalSolver
TopoResult kahnSort(Graph graph);

// TopoResult 的读取方法
List<String> getOrder();
boolean hasCycle();
```

无环时 `getOrder()` 包含每个节点一次，并满足每条边的起点排在终点前面。含环时 `hasCycle()` 为 true，序列返回空列表，避免把部分已处理节点误认为完整答案。空图返回空序列且 `hasCycle()` 为 false；界面层对没有有效数据的输入给出提示，不与图算法定义混淆。

E 检查正确性时应验证节点覆盖、无重复和全部边的先后关系，不要求与某一条人工答案逐字相同。若遍历顺序一致，单序列结果也应可复现，便于定位回归问题。复杂度目标是 O(V+E)，其中 V 为节点数，E 为边数。

## 四 多序列枚举

```java
// algorithm.AllTopoSorts，BooleanSupplier 来自 java.util.function
EnumerationResult enumerate(
    Graph graph,
    int maxResults,
    long timeoutMillis,
    BooleanSupplier cancelled
);

// EnumerationResult 的读取方法
List<List<String>> getSequences();
int getGeneratedCount();
boolean isComplete();
StopReason getStopReason();
```

`maxResults` 默认由调用方传入 1000，0 表示不设数量上限；`timeoutMillis` 为 0 表示不设时间上限，正数表示允许的运行时长，单位为毫秒。具体时限由 B 的调用配置传入，本契约不额外规定统一的超时默认数值。`cancelled` 用于让算法及时响应取消，测试时可传入始终为 false 的函数。数值为负等参数错误应明确拒绝，而不是静默改成另一种模式。

| 停止原因 | 含义 | 是否可以宣称已生成全部结果 |
| --- | --- | --- |
| `COMPLETED` | 已穷尽全部选择 | 可以，完整标记为 true |
| `LIMIT_REACHED` | 达到输出数量上限，尚未确认穷尽 | 不可以 |
| `CANCELLED` | 用户取消 | 不可以 |
| `TIMEOUT` | 达到运行时限 | 不可以 |
| `CYCLE` | 输入图含环，不进入枚举 | 显示无合法拓扑排序，区别于成功枚举 |

`getGeneratedCount()` 必须与实际返回序列数量一致，只有 `isComplete()` 为 true 时才作为确切总数显示。恰好生成到上限时，如果算法尚未证明没有更多结果，应保守地标记未完整。每条序列都需要复制保存，不能多条记录引用同一个回溯中的列表。

枚举入口应在展开搜索前拒绝含环图，确保 E 不经 GUI 直接调用也能安全终止。回溯必须恢复入度和候选状态，取消或超时后不得污染原图及后续计算。空图在算法层有一个空序列；正常完成枚举时返回 `[[]]`，生成数量为 1，完整标记为 true。界面层对空输入给出提示，E 分别验证输入层与算法层的行为。

## 五 环路径

```java
// algorithm.CycleDetector
List<String> findCycle(Graph graph);
```

返回值为空表示无环，有环时返回首尾相同的闭合节点序列，例如 `[A, B, C, A]`。自环可以表示为 `[A, A]`，路径中相邻节点必须对应真实存在的有向边。B 用它生成可读提示，C 用相邻节点对标红对应边，E 验证路径确实闭合且存在。

## 六 解析与输入校验

```java
// io.DataParser 的实例方法
ParseResult parse(String text);

// ParseResult 的读取方法
Graph getGraph();
List<ParseIssue> getErrors();
List<ParseIssue> getWarnings();
```

解析器由 D 实现，直接通过 A 的 Graph 方法建立图，并通过 `ParseResult.getGraph()` 返回 `model.Graph`。成功解析的关系均保存在该图中，自环也通过 `Graph.addEdge` 正常加入；B 的界面入口和 E 的命令行入口使用返回的图，无需根据边列表分别重建。解析器内部是否暂存边列表由 D 决定，对外仍提供本节规定的图和问题列表。

`getErrors()` 用于读取解析错误，`getWarnings()` 用于读取可继续处理的提示，例如重复关系；两者的元素类型均为 `ParseIssue`。有解析错误时，B 和 E 都不启动计算，也不把部分解析结果当成完整输入。没有解析错误不代表图非空或无环：无数据由输入层提示，自环及其他循环依赖由环检测报告，警告不能成为删除这些关系的理由。

`ParseIssue` 描述具体输入行的问题，包含从 1 开始的行号和原因。整份输入没有数据时由输入层给出整体提示，文件读取失败由文件读写层反馈实际原因，不强行编造问题行号。`InputValidator` 和 `DataParser` 必须复用同一套格式规则，统一处理空行、注释、课程名称内部空格和全角尖括号。

| 场景 | 处理规则 |
| --- | --- |
| 空白行、以 `#` 开头的注释行 | 跳过，不作为单行错误 |
| 整份输入没有有效节点和关系 | 输入层提示没有数据；Graph 本身仍允许为空 |
| 重复关系 | 去重，可提供提示，不能重复计入入度 |
| 自环 | 作为环保留，统一通过环检测提示 |
| 英文半角格式 | 必须支持，正式保存采用 `<a,b>` |
| 全角尖括号兼容 | 由 D 的解析与校验规则统一支持，接受范围写入数据格式说明，保存时转为英文半角标准格式 |
| 孤立节点 | Graph 通过 `addVertex` 保存；关系对语法只表示边，不用 `<A,A>` 表示孤立节点 |

## 七 绘图和导出

```java
// view.GraphPanel 的实例方法
void setGraph(Graph graph);
void setHighlightedCycle(List<String> closedCycle);
void exportPNG(File file) throws IOException;
```

`setGraph` 接收输入关系对应的 Graph，不能把没有直接关系的课程随意连在一起。环高亮只标记路径中的节点和边，新数据载入后清理旧高亮；选中排序序列的展示由 B、C 的界面流程组织，不改变原图关系。PNG 导出保存完整关系图，包含当前视口之外的节点与边，避免因缩放或滚动造成内容遗漏。

文件选择和取消由界面处理，文件写入错误通过异常反馈给 B 的统一提示入口。D 的排序结果导出应同时写明结果是否完整和停止原因，不能将截断结果标注为全部。导出编码、CSV 转义及图片边界由对应负责人实现并由 E 验证，本文件不代替他们的详细设计。

## 八 环境与版本维护

项目统一采用 Java＋Swing，目标 JDK 为 21，源码和文本数据使用 UTF-8。各成员按照本契约实现公共接口，测试使用相同的节点标识、关系方向和结果状态。JDK 版本约定不代表具体程序入口、JAR 文件或启动脚本已经生成，运行信息应与实际交付文件保持一致。

本契约规定跨模块的共同边界，具体布局、界面交互、输入扩展和文件输出细节由对应模块负责。孤立节点的额外输入语法不在本文的关系对格式中定义，B、D 在输入功能中提供相应能力时，应同步数据格式说明并保持与 Graph.addVertex 一致。只读视图与副本、独立图快照与禁止原图修改均是允许的实现方式，但都必须满足本文规定的数据保护和稳定输入要求。

公共方法签名、参数含义、返回状态或输入输出规则发生变化时，提出方说明影响范围，与相关调用方达成一致后更新契约、调用代码和测试。内部实现调整若不改变约定行为，可由模块负责人自行维护。版本号和修订说明随接口变更更新，不以修改文档代替实际实现及验证。
