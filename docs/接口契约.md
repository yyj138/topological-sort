# 跨模块接口契约草稿

本文件是 A 为 9 月 17 日接口会议准备的 V0.1 草稿，尚未经过全组确认，也不代表接口已经实现。目标是让 B 的界面、C 的绘图、D 的解析和 E 的测试能够围绕同一套数据结构开发。下方 Java 签名是建议设计，会议通过后再据此实现，变更时同步通知调用方。

## 一 职责和调用顺序

| 模块 | 提供者 | 输入与输出 |
| --- | --- | --- |
| Graph | A | 存储课程及有向关系，提供只读遍历 |
| TopologicalSolver | A | 图输入，返回一种完整拓扑序列或含环状态 |
| AllTopoSorts | A | 图和计算限制输入，返回若干序列、完整性与停止原因 |
| CycleDetector | A | 图输入，返回具体闭合环路径；无环返回空列表 |
| DataParser、InputValidator | D | 文本输入，返回图、错误和可提示的问题 |
| GraphPanel | C | 接收图和高亮节点，负责布局、绘图与图片输出 |
| MainController | B | 组织数据校验、绘图和后台计算，将返回状态展示给用户 |
| AlgorithmRunner 与测试 | E | 调用相同解析和算法接口，完成无界面联调与独立验证 |

建议界面先校验和解析输入，再显示关系图，判环后才尝试多结果枚举。B 负责后台任务及界面线程更新，A 的算法负责定期检查取消和超时，不从算法内部弹出窗口。耗时计算使用稳定的图快照或在计算期间禁止修改同一实例，这一点由 A、B、C 共同确认。

## 二 图结构

节点以去除首尾空白后的名称作为唯一标识，大小写是否区分建议采用区分方式，例如 A 和 a 是不同节点。关系 `<a,b>` 表示 a 必须先于 b，对应 a 指向 b。名称允许中文和内部空格，格式分隔符、换行和空名称不作为合法名称，具体字符规则由 D 在解析时统一执行。

```java
// model.Graph 的建议实例方法
boolean addVertex(String name);
boolean addEdge(String from, String to);
boolean removeEdge(String from, String to);
List<String> getVertexNames();
List<String> getSuccessors(String name);
int getInDegree(String name);
int getOutDegree(String name);
int getVertexCount();
int getEdgeCount();
```

`addEdge` 自动补齐两端节点，新边返回 true，重复边返回 false 且不重复增加入度。自环保留为一条边，由环检测报告，不通过忽略自环把错误数据变成无环图。查询未知节点的行为建议统一为抛出带明确信息的参数异常，B 或 E 在调用边界转换为提示或测试失败。

返回的节点和后继列表为只读视图或副本，调用者不能绕开 Graph 直接修改关系。节点和后继按录入顺序稳定遍历，便于复现结果；算法计算使用局部入度副本，不改变 Graph 的原始入度。`Vertex` 和 `Edge` 仍按任务卡设计，但绘图不依赖它们的可变内部字段。

## 三 单序列排序

```java
// algorithm.TopologicalSolver
TopoResult kahnSort(Graph graph);

// TopoResult 的建议读取方法
List<String> getOrder();
boolean hasCycle();
```

无环时 `getOrder()` 包含每个节点一次，并满足每条边的起点排在终点前面。含环时 `hasCycle()` 为 true，建议序列返回空列表，避免把部分已处理节点误认为完整答案。空图返回空序列且 `hasCycle()` 为 false；界面是否拒绝空输入由输入层决定，不与图算法定义混淆。

E 检查正确性时应验证节点覆盖、无重复和全部边的先后关系，不要求与某一条人工答案逐字相同。若遍历顺序一致，单序列结果也应可复现，便于定位回归问题。复杂度目标是 O(V+E)，其中 V 为节点数，E 为边数。

## 四 多序列枚举

```java
// algorithm.AllTopoSorts，BooleanSupplier 来自 java.util.function
EnumerationResult enumerate(
    Graph graph,
    int maxResults,
    long timeoutMillis,
    BooleanSupplier cancelled
);

// EnumerationResult 的建议读取方法
List<List<String>> getSequences();
int getGeneratedCount();
boolean isComplete();
StopReason getStopReason();
```

`maxResults` 默认由调用方传入 1000，0 表示不设数量上限；`timeoutMillis` 为 0 表示不设时间上限，界面采用的具体时限在会议中确认。`cancelled` 用于让算法及时响应取消，测试时可传入始终为 false 的函数。数值为负等参数错误应明确拒绝，而不是静默改成另一种模式。

| 停止原因建议值 | 含义 | 是否可以宣称已生成全部结果 |
| --- | --- | --- |
| `COMPLETED` | 已穷尽全部选择 | 可以，完整标记为 true |
| `LIMIT_REACHED` | 达到输出数量上限，尚未确认穷尽 | 不可以 |
| `CANCELLED` | 用户取消 | 不可以 |
| `TIMEOUT` | 达到运行时限 | 不可以 |
| `CYCLE` | 输入图含环，不进入枚举 | 显示无合法拓扑排序，区别于成功枚举 |

`getGeneratedCount()` 必须与实际返回序列数量一致，只有 `isComplete()` 为 true 时才作为确切总数显示。恰好生成到上限时，如果算法尚未证明没有更多结果，应保守地标记未完整。每条序列都需要复制保存，不能多条记录引用同一个回溯中的列表。

枚举入口应在展开搜索前拒绝含环图，确保 E 不经 GUI 直接调用也能安全终止。回溯必须恢复入度和候选状态，取消或超时后不得污染原图及后续计算。空图在算法层可约定有一个空序列，界面层对空输入给出提示；此边界由 A、B、E 在会议确认后统一测试。

## 五 环路径

```java
// algorithm.CycleDetector
List<String> findCycle(Graph graph);
```

返回值为空表示无环，有环时返回首尾相同的闭合节点序列，例如 `[A, B, C, A]`。自环可以表示为 `[A, A]`，路径中相邻节点必须对应真实存在的有向边。B 用它生成可读提示，C 用相邻节点对标红对应边，E 验证路径确实闭合且存在。

## 六 解析与输入校验

```java
// io.DataParser 的建议实例方法
ParseResult parse(String text);

// ParseResult 的建议读取方法
Graph getGraph();
List<ParseIssue> getErrors();
List<ParseIssue> getWarnings();
```

草案建议解析器直接通过 A 的 Graph 方法建图，并返回解析问题清单，避免 B 再次解析或重复建图。每条问题包含从 1 开始的行号和原因，有错误时 B 不启动计算，也不把部分解析结果当成完整输入。`InputValidator` 和 `DataParser` 必须复用同一套格式规则，不能一个允许空行而另一个拒绝。

| 场景 | 草案建议 |
| --- | --- |
| 空白行、以 `#` 开头的注释行 | 跳过，不作为单行错误 |
| 整份输入没有有效节点和关系 | 输入层提示没有数据；Graph 本身仍允许为空 |
| 重复关系 | 去重，可提供提示，不能重复计入入度 |
| 自环 | 作为环保留，统一通过环检测提示 |
| 英文半角格式 | 必须支持，正式保存采用 `<a,b>` |
| 全角尖括号兼容 | 原方案提出的容错扩展，D 说明接受范围，保存时转为标准格式 |
| 孤立节点 | Graph 支持 `addVertex`；文件或界面输入语法尚待确认，不用 `<A,A>` 表示 |

## 七 绘图和导出

```java
// view.GraphPanel 的建议实例方法，由 C 确认
void setGraph(Graph graph);
void setHighlightedCycle(List<String> closedCycle);
void exportPNG(File file) throws IOException;
```

`setGraph` 接收的是关系图，不是拓扑序列生成的链，不能把没有直接关系的课程随意连在一起。环高亮只标记路径中的节点和边，新数据载入后清理旧高亮；选中排序序列的显示方式由 B、C 另行对接。PNG 导出应明确保存整个图还是当前可视区域，草案倾向于完整关系图，最终由 C 与 B 确认，避免缩放后遗漏画面之外的节点。

文件选择和取消由界面处理，文件写入错误通过异常反馈给 B 的统一提示入口。D 的排序结果导出应同时写明结果是否完整和停止原因，不能将截断结果标注为全部。导出编码、CSV 转义及图片边界由对应负责人实现并由 E 验证，本文件不代替他们的详细设计。
