## 计算流程与返回规则

排序器先读取全部节点，将每个节点的入度复制到局部表，并按节点录入顺序把所有零入度节点加入队列。随后每次取出队首节点，加入输出序列，并依次减少其直接后继在局部表中的入度；某后继入度减到 0 时进入队尾。队列耗尽后，处理节点数等于总节点数表示排序成功，否则表示图中含环，此时丢弃已处理的部分序列。

| 输入或行为 | 结果与约定 |
| --- | --- |
| 普通无环图 | `hasCycle() == false`，序列包含全部节点且每个节点恰好一次，满足所有边的先后约束 |
| 含环图，包括自环 | `hasCycle() == true`，`getOrder()` 为空，不返回伪完整答案 |
| 空图 | `hasCycle() == false`，`getOrder()` 为空，区别于含环失败 |
| 孤立节点、不连通的无环分量 | 全部纳入完整序列，不只遍历一个起点能到达的部分 |
| null 图引用 | 抛出带原因的 `IllegalArgumentException` |
| 重复调用 | 所有计算状态为方法内局部变量，不复用上次调用的队列、入度或结果 |
| 输出保护 | 结果序列为不可修改副本，后续修改图或再次计算不会改变旧结果；类似”A1 中的只读快照“ |
| 遍历与线程边界 | 初始零入度节点按节点录入顺序入队，后续按后继遍历顺序入队；计算期间调用方须保证图不被并发修改 |

算法只读取 Graph，不删除原图的边，也不修改原图的入度。相同图及相同遍历顺序会得到稳定结果，但算法不承诺字典序最小，也不表示合法顺序只有这一种。忽略名称长度并按哈希表平均复杂度计，时间为 O(V+E)，辅助空间为 O(V)；具体环路径提取仍属于 A4。

调用方式如下，业务调用方应先判断 `hasCycle()`，再使用排序序列。示例中的 A 和 B 是手工节点，仅用于说明 API。结果类型和排序器均位于 `algorithm` 包。

```java
import algorithm.TopoResult;
import algorithm.TopologicalSolver;
import model.Graph;

Graph graph = new Graph();
graph.addEdge("A", "B");
TopoResult result = new TopologicalSolver().kahnSort(graph);
// result.hasCycle() 为 false，result.getOrder() 为 [A, B]。
```

## 编译与复现

在仓库根目录使用 JDK 21 和 UTF-8 执行以下 PowerShell 命令。编译开启全部警告，并将警告视为错误；失败即停止，避免误运行旧 class 文件。编译产物只保存在现有忽略目录 `out/a2` 中。

```powershell
javac -encoding UTF-8 --release 21 -Xlint:all -Werror -d out/a2 src/model/Vertex.java src/model/Edge.java src/model/Graph.java src/algorithm/TopoResult.java src/algorithm/TopologicalSolver.java test/GraphSelfTest.java test/TopologicalSolverSelfTest.java

java -cp out/a2 GraphSelfTest
if ($LASTEXITCODE -ne 0) { throw 'A1 回归失败' }
```

本次实际使用 `D:\jdk21\bin\javac.exe` 和 `D:\jdk21\bin\java.exe` 执行以上编译及测试，以明确使用 JDK 21.0.6。编译无警告，A2 测试及 A1 回归均以退出码 0 结束。A2 完整控制台输出保存在 [A2命令行自测输出样例.txt](A2命令行自测输出样例.txt)；不传图 1 文件参数时，自测程序只执行 18 组基础测试并明确提示图 1 未运行。

## 验证覆盖

| 自测组 | 检查重点 |
| --- | --- |
| 1—3 | 空图、单节点、节点逆序录入的链，确保排序遵循关系而非简单返回录入顺序 |
| 4—8 | 菱形依赖、多起点加孤立节点、全孤立节点、不连通无环分量、重复边 |
| 9—12 | 自环、两节点环、较长环及下游节点、无环分量与环共存时丢弃部分顺序 |
| 13—16 | 中文及内部空格名称、大小写、重复调用与跨图复用、只读结果、null 参数 |
| 17 | 枚举全部 $2^9=512$ 张三节点有向图（包含自环），逐图与六种节点排列的独立合法性检查对照 |
| 18 | 1000 节点、999 条边的链，检查所有节点顺序正确；这是正确性用例，不是性能基准 |
| 19 | D 提供的图 1：15 个节点、16 条边，检查节点覆盖、无重复、全部边的顺序和输入不变 |

每次测试排序都比较计算前后的节点顺序、后继列表、节点数、边数、各节点入度和出度。无环结果用节点集合、数量及逐边位置检查合法性；部分用例另外核对固定顺序，以验证队列策略的可复现性。第 17 组不复用 Kahn 的入度逻辑，而是尝试全部六种排列，确认其中 25 张图无环、487 张图含环，并逐一与排序器结果对照。
