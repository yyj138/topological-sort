```java
import algorithm.CycleDetector;
import model.Graph;
import java.util.List;

Graph graph = new Graph();
graph.addEdge("A", "B");
graph.addEdge("B", "C");
graph.addEdge("C", "A");
List<String> cycle = new CycleDetector().findCycle(graph);
// cycle 为 [A, B, C, A]。若列表为空，则表示无环。
```

返回值沿用 Graph 中的节点名称，B 可据此生成提示，C 可用相邻节点对识别待高亮的真实边。**列表首尾节点相同，自环返回两个相同节点，空图和其他无环图均返回空列表**。结果是不可修改的独立列表，后续修改图或再次调用不会改变旧结果；null 图引用会抛出带原因的 IllegalArgumentException。

## 实现流程

先调用 A2 的 `TopologicalSolver.kahnSort(graph).hasCycle()`，用已处理节点数判断图是否含环；无环直接返回空列表。含环时再按录入顺序遍历全部连通分量，使用三色标记开展 DFS：白色为未访问，灰色为当前搜索路径上的节点，黑色为已经完成后继遍历的节点。DFS 使用一张独立的颜色表记录节点的访问状态。节点名称尚未出现在表中时，就视为白色，表示还没有访问过。颜色表由本次搜索单独维护，不会把访问状态写入 Graph，也不会修改图中的节点或边。

DFS 使用显式栈保存每一层后继迭代器，并维护当前节点路径，从而避免长路径导致递归调用栈溢出。遇到指向灰色节点的边时，截取当前路径从该灰色节点开始的部分，再追加一次起点，形成闭合环；进入环之前的前缀不会混入结果。指向黑色节点的边不是当前路径的回边，不能仅因目标曾被访问过就认定有环。

本实现返回录入顺序下遇到的第一条环，不承诺最短环，也不枚举全部环。所有状态都是调用内的局部数据，原图的节点、边、入度和出度保持不变；调用方须保证 Kahn 与 DFS 整个计算期间输入图稳定。若 Kahn 判断含环却在 DFS 中找不到闭合路径，将明确报告判定不一致，而不是伪装成无环。

忽略名称长度、按哈希表平均复杂度计，Kahn 与 DFS 总时间为 O(V+E)。路径截取只在找到环时执行一次，不会在每条边上扫描当前路径。显式栈中会保留 Graph 返回的后继快照，因此辅助空间上界记为 O(V+E)，不将其误写为只保存访问标记所需的 O(V)。

## 至少三种环的实际检测记录

| 类型 | 输入边 | 实际闭合路径 |
| --- | --- | --- |
| 自环 | A → A | `[A, A]` |
| 两节点互相依赖 | A → B，B → A | `[A, B, A]` |
| 三节点构成长环 | A → B，B → C，C → A | `[A, B, C, A]` |
| 环外前缀接入环 | Start → A，A → B，B → C，C → B | `[B, C, B]`，不包含 Start 和 A |

以下是本次控制台输出的原文片段。每次返回非空路径时，自测程序都检查至少包含两个元素、首尾一致、环内节点存在且不重复，以及每对相邻节点间确实存在对应有向边。检测前后还比较节点录入顺序、后继列表、节点数、边数和各节点的入出度，确认没有污染输入图。

```text
Self-loop: edges=[A -> A], cycle=[A, A]
Two-vertex cycle: edges=[A -> B, B -> A], cycle=[A, B, A]
Longer cycle: edges=[A -> B, B -> C, C -> A], cycle=[A, B, C, A]
Prefix excluded: edges=[Start -> A, A -> B, B -> C, C -> B], cycle=[B, C, B]
```
