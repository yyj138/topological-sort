## 3.1 算法模块（A负责）

算法模块以有向图表示课程之间的先修关系，提供单个拓扑序列求解、多种拓扑序列枚举和环路径定位功能。图数据由 `model` 包维护，核心计算由 `algorithm` 包完成，结果对象向界面及文件模块提供统一的序列和状态信息。各算法使用独立的入度副本、访问标记和搜索路径，不修改原图；调用方在计算期间保持图稳定，使排序、环定位和绘图基于同一份关系数据。

### 3.1.1 类设计

**（1）图模型类**

图模型由 Graph、Vertex 和 Edge 组成，分别负责整图管理、节点关系保存和有向边描述。Graph 统一维护邻接关系，Vertex 的关系增删方法只供包内调用，外部模块通过查询接口读取数据。三个类共用名称校验规则，保留名称内部空格，并按录入顺序保存节点及关系。

| 类 | 职责 | 核心字段 | 主要方法 |
| --- | --- | --- | --- |
| `Graph` | 管理节点、边及关系查询 | `vertices`：`LinkedHashMap<String, Vertex>`；`edgeCount`：边数 | `addVertex(name)`、`addEdge(from,to)`、`removeEdge(from,to)`、`getVertexNames()`、`getSuccessors(name)`，以及入度、出度、节点数和边数查询 |
| `Vertex` | 保存节点名称及直接邻接关系 | `name`：节点名；`successors`、`predecessors`：`LinkedHashSet<String>` | `getName()`、`getSuccessors()`、`getInDegree()`、`getOutDegree()`；包内 `normalizeName(name)` 统一校验名称 |
| `Edge` | 表示不可变的有向边 | `from`、`to`：起点和终点名称 | `getFrom()`、`getTo()`、`equals(other)`、`hashCode()` |

Graph 的实际关系保存在 Vertex 的前驱、后继集合中，不另存一份 Edge 列表，创建 Edge 也不会自动修改图。添加边时自动补齐节点并去重，删除边后保留节点，自环则保留供算法检测。入度、出度由邻接集合大小计算，节点和后继查询返回不可修改的快照，避免外部直接破坏内部关系。

**（2）算法与结果类**

算法类读取 Graph 并返回统一的结果对象，计算状态在每次调用中独立创建。表中的“字段”指对象成员，入度数组、颜色表和搜索路径等局部变量在后续算法流程中说明。结果类对序列形成不可修改的快照，使界面和导出模块能够读取一致的结果与状态。

| 类或类型 | 职责 | 核心字段 | 主要方法或取值 |
| --- | --- | --- | --- |
| `TopologicalSolver` | 使用 Kahn 求一种合法拓扑顺序 | 无持久计算字段 | `kahnSort(Graph graph)`，返回 `TopoResult` |
| `TopoResult` | 封装单序列排序结果 | `order`：排序列表；`hasCycle`：含环标记 | `getOrder()`、`hasCycle()` |
| `AllTopoSorts` | 枚举合法拓扑序列并控制搜索规模 | `nanoTime`：`LongSupplier` 单调时钟 | `enumerate(graph,maxResults,timeoutMillis,cancelled)`；私有 `undo(...)` 恢复状态，`interruption(...)` 检查中断 |
| `CycleDetector` | 定位一条闭合环路径 | 无持久搜索字段；内部 `Color` 枚举定义灰、黑两色，未访问节点视为白色 | `findCycle(Graph graph)`，返回闭合路径或空列表 |
| `EnumerationResult` | 封装枚举序列及停止状态 | `sequences`：`List<List<String>>`；`stopReason`：停止原因 | `getSequences()`、`getGeneratedCount()`、`isComplete()`、`getStopReason()` |
| `StopReason` | 统一描述枚举停止原因 | 无业务字段 | `COMPLETED`、`LIMIT_REACHED`、`CANCELLED`、`TIMEOUT`、`CYCLE` |

TopoResult 在含环时返回空序列，避免将局部前缀误认为完整答案；CycleDetector 只定位第一条环，不保证最短环或全部环。EnumerationResult 的数量由序列集合大小计算，完整性由停止原因推导，不额外保存这两个字段。只有 COMPLETED 表示已穷尽搜索，达到上限、取消或超时均不能将已生成数量当作确切总数。

### 3.1.2 核心算法流程

**（1）Kahn 排序流程**

Kahn 算法首先读取全部节点，将原始入度复制到局部映射，并把所有零入度节点按录入顺序加入先进先出队列。每次取出队首节点加入结果，遍历它的直接后继并减少后继的局部入度，后继入度降为零时加入队列。队列为空后比较已处理节点数与节点总数，相等表示得到完整拓扑序列，否则判定含环并丢弃已得到的局部前缀。

```text
读取节点集合，复制入度到 degree
将全部零入度节点按录入顺序加入队列 Q
order ← 空序列
while Q 非空:
    u ← 队首出队
    将 u 加入 order
    for v in u 的直接后继:
        degree[v] ← degree[v] - 1
        若 degree[v] = 0，将 v 加入 Q
若 order 长度等于节点总数:
    返回 TopoResult(order, false)
否则:
    返回 TopoResult(空序列, true)
```

每次出队的节点都没有尚未处理的前驱，因此将其追加到结果不会违反先修关系。例如 A→C、B→C 的初始零入度队列为 A、B，依次处理后 C 的剩余入度降为零，最终得到 `[A,B,C]`。同一录入顺序下结果稳定，但这只是一种合法顺序，不保证字典序最小，也不能据此判断答案是否唯一。

**（2）DFS 全枚举回溯流程**

全枚举将 Kahn 中的一次零入度选择扩展为对所有合法候选的逐一尝试。算法先把节点名称转换为整数下标，复制邻接关系与入度，再通过独立入度副本执行带取消、超时检查的 Kahn 判环；确认含环时直接返回 CYCLE，不进入回溯。无环时从深度 0 开始，每层只选择尚未使用且剩余入度为零的节点，选择后减少其后继入度并进入下一层。

实现采用显式数组模拟深度优先搜索，不递归调用 Java 方法。`nextCandidate[depth]` 保存当前层下次尝试的节点下标，回退后继续扫描该层尚未尝试的候选；进入新的一层时则将其扫描位置重置为 0。深度达到节点总数时复制保存完整序列，随后检查数量上限或回退，撤销上一层选择时清除 used 标记并恢复后继入度。

```text
校验参数，记录开始时间
复制节点、邻接数组和入度，执行 Kahn 判环
若收到取消或达到时限，返回相应状态
若图含环，返回 CYCLE
若图为空，返回包含一个空序列的 COMPLETED 结果
初始化 used、order、nextCandidate，令 depth = 0
while depth >= 0:
    检查取消与超时，必要时返回已保存的完整序列
    if depth 等于节点总数:
        将 order 转换为节点名称序列，复制后加入 results
        若达到正数数量上限，返回 LIMIT_REACHED
        depth ← depth - 1
        撤销 order[depth] 的选择，恢复后继入度
    else:
        从 nextCandidate[depth] 继续寻找未使用的零入度节点
        若找到候选 u:
            标记 u 已使用，记录 order[depth]，减少 u 的后继入度
            depth ← depth + 1，重置新层的候选扫描位置
        否则:
            depth ← depth - 1
            若仍在搜索树内，撤销父层选择并恢复入度
返回 COMPLETED
```

对于 A→C、B→C，第一层可以先选择 A，也可以先选择 B，两个分支分别得到 `[A,B,C]` 与 `[B,A,C]`。每层的零入度约束保证当前前缀合法，used 标记保证节点不会重复，路径达到完整长度后才保存结果。任意合法拓扑序列的下一节点都是相应状态下的可选节点，因此穷尽全部分支能够覆盖所有合法序列；同一层不重复尝试同一候选，避免生成重复排列。

**（3）环检测三色标记流程**

CycleDetector 先调用 Kahn 判断是否含环，无环时直接返回空列表。含环时使用三色标记进行深度优先搜索：白色表示未访问，灰色表示位于当前搜索路径，黑色表示其全部后继已经处理完成。算法按节点录入顺序依次选择白色根节点，通过显式迭代器栈推进和回退，因此能够覆盖不连通分量，也避免长路径引发递归调用栈溢出。

```text
若 Kahn 判定无环，返回空列表
初始化颜色表 colors、当前路径 path 和迭代器栈 stack
依次从每个白色节点开始搜索:
    将根节点标灰，加入 path，压入其后继迭代器
    while stack 非空:
        若栈顶仍有下一后继 v:
            v 为白色：标灰、加入 path，并压入 v 的后继迭代器
            v 为灰色：截取 path 从 v 开始的后缀，末尾追加 v，返回环
            v 为黑色：继续检查其他后继
        否则:
            弹出迭代器，将 path 末尾节点移出并标黑
```

指向灰色节点的边与当前路径中的一段共同形成闭合有向环，指向黑色节点则只表示到达已经处理完成的分支。例如当前路径为 X→A→B→C，遇到 C→A 时返回 `[A,B,C,A]`，不包含进入环之前的 X；遇到 A→A 时返回 `[A,A]`。若 Kahn 已判环而 DFS 却未能找到路径，实现会抛出状态异常，提示检查计算期间图是否被修改，而不是将不一致结果当成正常无环状态。

### 3.1.3 核心算法设计

**（1）算法复杂度**

设节点数为 n，边数为 m，实际访问的枚举搜索状态数为 P，返回的完整序列数为 R。以下分析忽略名称字符串长度，将哈希表操作按平均常数时间计算，并计入当前实现返回列表快照的开销。Graph 以邻接关系存储节点及边，空间为 O(n+m)，算法辅助空间则在原图之外单独分析。

Kahn 排序中，每个节点最多入队和出队一次，每条边触发一次入度更新，因此时间为 O(n+m)。局部入度映射、队列和排序结果均至多保存 n 个节点，辅助空间为 O(n)。查询直接后继产生临时快照，但单个节点的去重后继数不超过 n，不改变这一辅助空间上界。

环检测包含一次 Kahn 预判和一次三色 DFS，两部分的时间均为 O(n+m)。发现第一条环后，定位灰色节点在路径中的位置并复制环路径至多花费 O(n)，因此整体时间仍为 O(n+m)。颜色表与路径需要 O(n) 空间，显式栈还持有各层后继列表快照，当前实现的辅助空间上界为 O(n+m)。

全枚举的图复制与预判需要 O(n+m) 时间，每个搜索状态最多扫描 n 个候选，选择与恢复时还需更新所选节点的后继入度。由于单个节点的直接后继不超过 n，结合复制 R 条长度为 n 的完整序列，时间上界可写为 O(n+m+Pn+Rn)。局部图副本和搜索数组占 O(n+m)，保存结果占 O(Rn)，总辅助空间上界为 O(n+m+Rn)；无边图有 n! 种合法顺序，全枚举不能沿用单序列排序的线性复杂度结论。

**（2）候选筛选与无效分支排除**

算法通过拓扑约束减少无效搜索，而不是先产生全部排列再逐条判断。每层只尝试未使用且剩余入度为零的节点，排除重复节点和仍有前驱未处理的选择，因此进入下一层的前缀始终满足依赖关系。枚举前先判环，能够直接拒绝不存在合法拓扑序列的输入，避免在含环图中进行无意义的排列尝试。

候选扫描位置由 nextCandidate 保存，分支回退后继续尝试本层剩余节点，不重新尝试已经展开过的同层候选。若当前层没有剩余候选，则回退到父层，恢复该次选择之前的入度和使用标记，继续其他分支。这种筛选与状态恢复保证合法序列不会因错误剪枝而遗漏，但无法消除约束较少时合法结果本身的大量增长。

**（3）数量上限与结果完整性**

`maxResults` 为正数时，算法每保存一条完整序列就检查是否达到上限，达到后立即返回 LIMIT_REACHED；为 0 时不设数量限制，负数则作为非法参数拒绝。默认 1000 条由调用方传入，并非 AllTopoSorts 内部固定的不可变常量。数量限制控制本次返回结果的规模，但它属于提前停止，不是证明剩余分支不存在的正确性剪枝。

达到上限时，即使已生成数量恰好等于真实总数，算法也尚未确认剩余搜索已经穷尽，因此保守地标记未完整。只有正常遍历完全部分支才返回 COMPLETED，并由 `isComplete()` 给出 true；空图正常完成时按算法定义返回一个空序列。界面和导出模块应同时读取数量、完整性与停止原因，不能仅凭结果列表长度宣称已经列出所有答案。

**（4）超时与取消保护**

`timeoutMillis` 为正数时设置运行时限，为 0 时关闭时间限制，负数参数拒绝。计时从参数检查之后、图复制之前开始，覆盖数据复制、Kahn 预判和枚举阶段，使用单调时钟避免系统日期调整影响耗时判断。毫秒通过 `TimeUnit.MILLISECONDS.toNanos` 转换为纳秒，利用饱和转换避免极大参数在单位换算时发生乘法溢出。

算法在图复制、判环、候选扫描及完整序列构造等位置调用 interruption，先检查取消函数，再检查是否达到时限。取消时返回 CANCELLED，超时时返回 TIMEOUT，已有完整序列继续保留，尚未构造完的序列不加入结果。两者均为协作式检查，并非强行终止线程；单次集合复制、状态更新和返回结果封装等操作仍可能产生额外耗时，因此时限不能解释为方法必定在指定毫秒数内完成返回。

取消函数由调用方提供，应快速返回且不修改图，函数自身抛出的异常按实现向上传递。Graph 或取消函数为 null 时，枚举入口同样拒绝执行，避免将非法参数静默转换为另一种行为。当前 GUI 可以传入 1000 条、30 秒及取消状态，其他调用者则可选择不同限制，报告和测试需要说明各自实际参数。

**（5）原图保护与状态独立**

Kahn、全枚举和环检测都将本次计算状态保存在局部变量中，避免不同调用之间共享入度、颜色或路径。全枚举对正常分支回退执行 undo，取消或超时提前返回时则丢弃剩余局部搜索状态，无需将其恢复后再交给其他调用。原始 Graph 的节点、边和度数始终不由算法修改，但 Graph 本身不保证线程安全，调用方仍须保证计算期间不修改输入图。

每条输出序列在保存时形成独立快照，EnumerationResult 再将外层集合及各条序列封装为不可修改的结果。这样既防止工作数组被回溯修改后污染历史结果，也避免调用方通过返回列表改变其他模块正在读取的数据。显式搜索结构、局部状态和结果快照共同支持重复计算，但数量上限与超时并不等于固定内存上限，大量长序列仍需要结合实际规模控制资源使用。
