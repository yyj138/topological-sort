## 一、分析结论与依据

本项目采用 Java＋Swing 开发桌面拓扑排序应用，按现有任务范围具备实施可行性。依据是课程关系能够表示为有向图，基础拓扑排序和环检测有清晰的实现路径，界面、解析、算法与测试可以按统一接口分工完成。可行性成立的主要条件是尽早明确接口、控制多序列枚举的计算规模，并在最终验收前完成跨模块联调与目标环境验证。

本文依据课程任务书、团队任务执行方案、A5 V1.0 接口契约、图数据结构设计和 B 的需求报告编写。A1 图模型、A2 Kahn 排序、A4 环路径定位及 A3 枚举初版已有代码，9 月 18 日保存的验证记录显示在 JDK 21.0.6 下严格编译通过，作者自测分别通过 16、19、19、25 组。这些结果支持核心算法路线的可行性，但不代替 E 的独立测试，也不能证明 GUI、正式解析器和导出已经完成整体联调。

项目的核心不确定性是合法拓扑序列的数量可能随输入迅速增加。软件可以通过明确的结果上限、取消和运行时间控制维持可操作性，但不能据此声称已经列出任意图的全部结果。本文将数量限制和千节点测试视为团队实施方案与验证目标，不把它们写成教师规定的统一性能指标。

## 二、项目目标与功能范围

软件面向需要理解课程先修关系和合法学习顺序的使用者。用户通过窗口输入或导入关系文本，查看相应有向图，执行拓扑排序，并保存关系图和排序结果。系统需处理无效输入及循环依赖，说明无法排序或仅得到部分结果的原因。

| 功能范围 | 拟达到的效果 | 约束与说明 |
| --- | --- | --- |
| 关系输入与文件导入 | 接收一行一条的课程关系，形成统一图模型 | 使用文本数据，关系方向和名称规则保持一致 |
| 图形界面与关系图显示 | 在桌面窗口显示课程节点和直接依赖边 | 满足非网页应用要求，具体布局由可视化模块设计 |
| 单序列排序与环检测 | 给出一种合法顺序，或指出循环依赖 | 含环时不能将部分处理结果当成完整拓扑序列 |
| 多序列枚举 | 尽可能生成多种不同的合法顺序 | 受数量、时间或取消影响时明确标记未完整 |
| 关系图与结果导出 | 保存图形文件和排序结果文本 | 结果导出保留生成数量、完整性和停止原因 |
| 两类数据验证 | 用任务书图 1 和真实课程关系检验应用 | 数据来源正确性与算法计算正确性分别核对 |

基本功能先形成“输入、建图、计算、显示、导出”的完整流程，再安排不影响主流程的扩展。搜索、缩放或更丰富的交互是否纳入本轮实现，**应与 B 的需求范围一致，不能由一份报告单方面增加承诺**。命令行调用用于独立验证算法和帮助定位问题，最终软件仍需提供图形操作界面。

## 三、技术可行性

### 1. 开发语言与界面技术

Java 可用于实现类、集合、文件处理和图算法，Swing 用于构建桌面窗口及自绘图形。团队契约与 B 的需求报告均采用 JDK 21、UTF-8 和 JDK 标准库，不把外部绘图库作为前置条件。目标版本已明确，各成员和验收电脑的实际编译、运行仍需逐一验证，不能从一台机器运行成功推断跨平台验证完成。

算法与图模型不依赖界面，可以通过手工建图和命令行入口先行检查。界面、绘图和文件模块接入同一套公开方法，能减少因各自重复保存关系而造成的不一致。技术选择的主要优势是职责能够拆分，主要成本则是成员仍需要掌握 Java 集合、异常处理、Swing 事件与后台任务等实际用法。

### 2. 图存储与基础算法

图模型已采用 LinkedHashMap 保存名称到节点的映射，并以 LinkedHashSet 记录直接前驱与后继，稳定保留录入顺序。该方式能够表示普通课程依赖、孤立节点、重复输入后的去重结果和循环依赖，并提供遍历与度数信息。关系修改统一经过 Graph，查询列表为不可修改的独立快照，算法使用局部状态，自测检查了重复调用和中断后原图不变。

Kahn 算法通过反复处理入度为零的节点生成一种合法顺序，在适当的邻接表和队列实现下，时间复杂度为 O(V＋E)。若处理节点数不足以覆盖全图，说明存在环；DFS 三色标记可进一步给出一条具体闭合路径。V 表示节点数，E 表示边数，这里的复杂度是算法分析，不是当前项目的实测耗时。

### 3. 多结果枚举与规模限制

多序列枚举初版已使用显式回溯，在多个当前可选节点之间分别尝试，保存合法完整序列，并在返回上一层时恢复临时状态。A3 已将全部 512 张三节点有向图的结果与独立排列过滤结果比较，但结果规模仍是主要限制。例如 n 个互不约束的节点共有 n! 种排列，生成和保存这些结果本身就需要大量时间与空间。

现有 A5 V1.0 契约采用调用方默认传入 1000 条、0 表示不限数量的方案，并提供取消及超时参数。达到上限并不证明总数等于上限，只有穷尽全部选择时才能报告确切总数；B 分支已按契约统一配置为 1000 条、30 秒，保留取消入口；默认配置差异已解决。A3 和 A4 已避免依赖递归调用栈，但千节点测试仍须结合边数、图形、结果限制和内存占用分析，不能承诺任意千节点图都可快速完整枚举。

### 4. 界面响应与模块集成

B 的 GUI 设计已采用 SwingWorker 组织后台枚举，A3 已实现取消与时间检查，计算结果通过停止原因区分完成、限量、取消、超时和含环。计算期间需保证输入图稳定，并验证旧任务结束后不会覆盖新任务的结果；具体控制责任仍须联调确认。仅看到后台线程或取消按钮存在，不能证明取消后保留结果、再次计算和界面响应均已正确。

联调可以从一个小的无环图开始，依次接通解析、Graph、单序列排序、绘图及导出。随后加入含环输入、多序列结果、取消和异常文件等情况，逐步扩大验证范围。这种顺序能尽早发现接口与数据含义的偏差，降低最后一次性整合全部模块的风险。

## 四、资源与经济可行性

当前方案主要使用成员现有电脑、JDK、编辑器和团队仓库，基本功能无需预先采购专用硬件。应用以本地桌面程序和文本文件为基础，也不把独立数据库或服务器部署作为必需条件。上述选择有利于控制新增资源需求，但团队尚需确认是否存在额外工具、存储或其他费用，本文不虚构具体预算，也不直接承诺总成本为零。

项目的主要投入是成员学习、设计、实现、测试和文档整理所需的时间。若基础功能尚未打通，应优先保证正确性和联调，而不是引入需要额外学习与部署的新框架。新增依赖确有必要时，应说明解决的问题、使用成本和对验收环境的影响，再调整方案。

## 五、操作与人员可行性

界面拟围绕输入、计算、查看和导出组织操作，使使用者无需编写代码即可完成课程关系分析。格式错误应指出具体原因，循环依赖应给出可理解的路径，部分枚举应说明停止原因。实际易用性还需在界面实现后通过操作演示核对，当前不能仅凭设计声称已经达到良好使用体验。

| 角色 | 主要职责 | 对其他模块的主要交付 |
| --- | --- | --- |
| A | 图结构、排序与环检测、公共约定及相关报告 | Graph、算法结果、设计说明和自测记录 |
| B | 需求分析、界面和主流程集成 | 已确认的功能范围、调用流程和用户反馈 |
| C | 关系图布局、绘制与图形导出 | 可读取 Graph 的画布、实际显示效果与截图 |
| D | 输入解析、文件处理及课程数据 | 解析结果、共享数据、结果导出与相关文档 |
| E | 测试、运行入口与材料整理 | 独立验证记录、运行说明及实际会议记录 |

已有分工说明任务能够拆分，但并不能自动证明每个人的时间与熟练程度都足够。成员需结合自己的安排确认近期交付，卡点应尽早反馈给依赖方。A 负责协调公共部分，不应默认由某一个人补完所有延期模块，确需调整时应明确新的责任和时间。

## 七、主要风险与应对

| 风险 | 可能造成的影响 | 应对方式与验证依据 |
| --- | --- | --- |
| 接口含义或数据方向不一致 | 解析、算法和绘图不能正确衔接 | 统一关系方向与结果结构，用同一小图进行跨模块核对 |
| 合法序列过多 | 计算时间和内存增加，界面响应变差 | 数量与时间限制、取消机制、完整性标记，并保存真实测试条件 |
| 成员环境或投入差异 | 编译失败、模块交付延迟 | 尽早统一 JDK 与运行方式，按可用时间安排最小交付 |
| 原图与计算状态相互影响 | 重复计算、取消或切换输入后结果错误 | 算法使用局部状态，上层保证稳定输入，核对计算前后图内容 |
| 图 1 或真实课程关系录入不准确 | 算法满足错误输入却得出错误应用结论 | D 与 A 核对原始依据，保留正式数据来源，再检查输出约束 |
| 图形布局与导出不完整 | 关系难以辨认，导出遗漏内容 | C 使用代表性图检查节点、箭头、文字和图形边界 |
| 联调或文档集中到最后 | 缺少运行证据，版本与说明不一致 | 提前打通主流程，持续整理真实结果，最终从交付目录复现 |

风险控制需要与实际开发相结合，而不只是写入报告。每个模块发现影响其他人的问题后，应说明触发条件、影响和拟采取的处理方式。测试记录应保留输入、预期、实际结果及环境，以支持后续修订和最终结论。

## 八、验证安排与定稿依据

验证首先使用可人工核对的小图，检查节点覆盖、边约束、环路径和枚举集合，再使用任务书图 1 和真实课程数据检查完整应用流程。单序列不能仅与某一个手工答案逐字比较，多序列应检查重复和遗漏，环路径应检查相邻节点之间确实存在对应边。绘图、导出和运行环境则需要各模块完成后进行实际操作验证。

已取得 D 整理的 `data/figure1.txt`，15 个节点、16 条边，原作者验证输入 SHA-256 为 `9A03F2F10ACF96808708BCDE1BFD3F50C66D79556B37156A2F18F597AB211137`。9 月 18 日 A3 记录完整生成 31,185 条，与独立子集动态规划计数一致，单次调用耗时 50.863 ms，不含结果检查与写文件。

9 月 19 日，D 的正式解析器与 A 模型、算法在固定版本上完成试接：解析器 35 项、预检 39 项、专门试接检查 43 项均通过；U+2003 名称处理、制表符重复键碰撞及首尾 Unicode 行分隔符漏检均已回归。任务书原始图 1 的 15 个节点和 16 条连线与正式输入逐项对应；原图没有箭头，方向沿用团队“先修到后修”及图中由下向上的解释，不据此虚构教师额外方向说明。正式解析后 Kahn 结果合法，完整枚举 31,185 条，COMPLETED、完整标记 true，逐条节点覆盖、边约束、唯一性和原图不变检查通过。

B 的 `cf96a11` 集成数据中，`curriculum.txt` 的解析、43 节点、85 条边和无环检查已通过；这些检查不等于核对 D 最新课程数据的原始培养方案，也不证明完整 GUI 和导出流程通过。真实课程来源、适用年级、映射与应用验证仍待 D、E 配合，性能结论待独立测试和必要优化。
