## 二、测试结果

### 测试 1：图 1 达到上限导出 — 通过

**操作**：

- 载入 `figure1.txt`；

- 点 “计算”；

- 点 “导出结果”，保存为 txt。
**检查结果**：

- 导出文件头写：

    ```Plain Text
    # 共 1000 条序列
    # 是否完整：否
    # 停止原因：达到输出上限，仅显示前 1000 条
    ```

- 导出内容为 1000 条，不是当前页 20 条；

- 文件命名和文件头均未标注 “全部结果”。
**结论**：通过。

---

### 测试 2：换输入后导出 — 通过

**操作**：

- 载入 `curriculum.txt`；

- 点 “计算”；

- 点 “导出结果”，保存为 txt。
**检查结果**：

- 导出内容属于 `curriculum.txt` 这次计算的结果，不是 `figure1.txt` 的旧结果；

- 文件头写的节点数、边数、停止原因都属于新计算；

- 未出现 “内容是旧结果，文件头写新结果停止原因” 的情况。
**结论**：通过。

---

### 测试 3：取消后导出 — 通过

**操作**：

- 载入 `curriculum.txt`；

- 点 “计算”；

- 枚举过程中点 “取消计算”；

- 点 “导出结果”，保存为 txt。
**检查结果**：

- 导出文件头写：

    ```Plain Text
    # 拓扑排序结果
    # 共 191312 条序列
    # 是否完整：否
    # 停止原因：用户取消
    ```

- 导出内容为已生成的完整序列，未混入不完整序列；

- B 的取消按钮、A 的取消响应、D 的导出逻辑均正常。
**测试条件说明**：

- 默认 `MainController.MAX_RESULTS = 1000` 时，图 1 和 `curriculum.txt` 的枚举都很快，用户几乎来不及点 “取消计算”；

- 为了触发取消，临时把 `MAX_RESULTS` 从 1000 改成 `Integer.MAX_VALUE`，使枚举时间变长；

- 测试完成后已恢复 `MAX_RESULTS = 1000`。
**结论**：通过。D 的导出逻辑能正确写入取消状态；默认配置下取消按钮难以触发的问题，属于 B 的 `MainController` 设计范围，已另行反馈。

---

### 测试 4：界面只显示第一页时导出 — 通过

## 四、D 的导出实现说明（供参考）

D 的 `FileManager` 提供两个重载：

```java
exportTxt(File file, List<String> results)
exportTxt(File file, List<String> results, boolean isComplete, String stopReasonText)
exportCsv(File file, List<String> results)
exportCsv(File file, List<String> results, boolean isComplete, String stopReasonText)
```

正式业务导出使用带 `isComplete` 和 `stopReasonText` 的重载，文件头写入：

```Plain Text
# 共 N 条序列
# 是否完整：是/否
# 停止原因：XXX（仅当不完整时写入）
```

`isComplete` 和 `stopReasonText` 由 B 的 `MainController` 从 A 的 `EnumerationResult` 转换后传入，`FileManager` 不 import `algorithm` 包。
