# 图数据结构设计草稿

本文件对应 T-A1 的设计准备，目前尚未实现 `Vertex`、`Edge` 或 `Graph`。图需要同时服务解析、算法和绘图，因此优先确定存储规则与遍历接口，再编码。建议接口见上一级的 [接口契约](../接口契约.md)，相关设计待 9 月 17 日评审。

## 存储方案

| 对象 | 建议保存的内容 | 责任 |
| --- | --- | --- |
| Vertex | 课程名称、后继与前驱标识集合 | 表达一个节点和直接关系 |
| Edge | 起点、终点名称 | 表达一条有向关系，按两端名称比较 |
| Graph | 名称到 Vertex 的映射、节点及边统计 | 统一维护关系变更，提供只读查询 |

名称到节点的映射和邻接集合建议保留插入顺序，保证遍历结果可复现，集合用于自然去重。原方案提到的“入度数组”可以在算法计算时根据节点索引建立，Graph 的原始入度由前驱集合大小得到，避免长期维护多份容易不同步的数据。是否接受该细化方案需 A 与 C、D 确认，不能视为已通过的接口变更。

## 基本操作

添加节点时先处理名称规则，已有名称不重复插入。添加边时补齐缺失的端点，只有新关系才更新后继、前驱和边数；删除边时同步更新两端关系。自环计为一条真实边，其入度和出度各增加一次，由后续环检测解释该输入为什么不能排序。

查询节点和后继时返回只读数据，绘图可以获取名称、后继、入度、出度和统计信息。布局坐标、颜色、缩放比例不存入 Graph，由 C 的画布管理。算法读取 Graph 后建立局部入度副本，反复排序和取消计算不能改变原始关系。

## 计划自测

| 小图 | 要检查的行为 |
| --- | --- |
| 空图 | 节点数和边数为 0，可遍历 |
| 单独 A | 能通过 `addVertex` 保存孤立节点 |
| A 指向 B | 自动补齐节点，A 出度与 B 入度为 1 |
| 两次加入 A 指向 B | 第二次不改变边数和入度 |
| A 指向 A | 保留自环，不误认为无边 |
| 删除 A 指向 B | 后继、前驱、入度与边数同步更新 |
| A 指向 C，B 指向 C | C 入度为 2，遍历能得到两条关系 |
| 查询后再重复计算 | 不能通过返回列表修改图，计算不污染原图 |
