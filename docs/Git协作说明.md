# Git 协作说明

项目统一使用 GitHub 仓库 `yyj138/topological-sort`，A 使用 `dev-a` 分支保存自己的开发成果。仓库已有的其他成员分支继续保留，其他人根据团队约定选择个人分支。`main` 用于经过审查的共享版本，个人分支推送成功不等于已经合入 `main`。

## 日常工作流程

开始工作前先确认当前分支和工作区状态，再读取远程更新。`git fetch origin` 只更新远程信息，不会自动把别人的修改合并进你的文件。需要接入其他分支时先检查差异，再按团队约定处理，避免在有未提交修改时随意切换或合并。

```powershell
git status
git branch --show-current
git fetch origin
```

完成一个有明确用途的改动后，检查本次修改，暂存指定文件并创建本地提交。提交说明带任务编号和实际行为，例如 `【T-A5】起草排序与图结构接口契约`；草稿必须注明待评审，不写成已经全员确认。提交记录用于追踪真实成果，不按文件数量拆分无意义提交。

```powershell
git diff
git add docs/接口契约.md docs/代码规范.md
git diff --cached
git commit -m "【T-A5】起草接口契约和代码规范"
```

第一次上传 A 的分支使用下面的命令，它会建立本地分支和远程分支的对应关系。之后在该分支中使用 `git push` 上传新提交，并通过 GitHub 页面或远程分支信息核实结果。不要强制推送或改写其他成员已经依赖的提交。

```powershell
git push -u origin dev-a
```

## 阶段成果与个人日志

源码、接口文档、设计稿和实际验证结果属于项目成果，应按任务进度提交到仓库。个人日志只在用户明确要求整理时生成，保存在仓库之外，用于后续个人总结和阶段汇报，不上传 GitHub。会议记录、项目报告和个人任务及感想按课程提交要求另行整理，不能把未来计划写成已经完成的工作。

## 合并与权限

合并前由负责人检查涉及的模块，至少确认工程能编译，并执行与改动相关的验证。当前约定不等于仓库已配置强制分支保护，实际保护设置需仓库所有者管理。A 当前具有写入权限；本轮将成果推送到 `dev-a`，合入 `main` 在明确安排后执行。

## 不提交的内容

编译产物、缓存、密码和临时文件不应放入源码提交，现有 `.gitignore` 已忽略 `.class`、`.jar`、压缩包和构建目录。验收发布物如何分发应在打包阶段单独安排，不因忽略规则而误以为已经上传。学校要求的最终压缩包仍需按规定上传 mySTU，不能用 GitHub 仓库链接代替。
