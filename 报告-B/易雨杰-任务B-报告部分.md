## 一、需求分析

### 1.1 项目背景
拓扑排序是有向无环图（DAG）中常用的线性排序算法，广泛应用于课程先修安排、任务调度、构建依赖分析等场景。本项目要求实现一个基于图形界面的拓扑排序工具，不仅能输出单条拓扑排序结果，还要枚举所有可能的合法拓扑排序，并通过可视化方式直观展示图结构和排序过程。

### 1.2 功能需求
根据任务书要求，结合小组讨论确定的功能需求如下：

| 需求分类 | 具体需求 | 说明 |
|---------|---------|------|
| 输入功能 | 文本输入 | 支持直接在文本框粘贴"先修,后继"格式的关系数据 |
| 输入功能 | 文件导入 | 支持从TXT文件读取关系数据，自动识别空行和注释 |
| 解析功能 | 自动建图 | 解析关系数据构建有向图，自动去重、识别自环 |
| 解析功能 | 错误提示 | 输入格式错误时标注行号，明确指出错误位置 |
| 核心算法 | 单条拓扑排序 | 基于Kahn算法输出一条合法拓扑序列 |
| 核心算法 | 全拓扑排序枚举 | 基于DFS回溯枚举所有合法拓扑排序，默认上限1000条 |
| 核心算法 | 环检测 | 自动检测图中的环，有环时提示并可视化环路径 |
| 可视化 | 图渲染 | 分层/环形双布局展示有向图，节点和边清晰可辨 |
| 可视化 | 交互操作 | 支持滚轮缩放、拖拽平移、节点位置拖动 |
| 可视化 | 联动高亮 | 点击结果列表，图上同步高亮该拓扑序的节点和顺序 |
| 导出功能 | 结果导出 | 支持将排序结果导出为TXT和CSV格式 |
| 导出功能 | 图片导出 | 支持将当前关系图导出为PNG图片 |
| 容错功能 | 超时保护 | 计算30秒未完成自动停止，避免程序无响应 |
| 容错功能 | 取消计算 | 计算过程中可随时取消，保留已生成的结果 |

### 1.3 非功能需求
1. **跨平台**：使用Java Swing开发，Windows/Linux/macOS均可运行
2. **零依赖**：纯JDK标准库实现，无需安装任何第三方依赖
3. **易用性**：界面简洁，操作逻辑清晰，新用户可快速上手
4. **性能**：100节点以内的图计算秒级完成，结果列表分页显示不卡顿

## 二、GUI 模块详细设计

### 2.1 整体架构
本项目GUI采用经典的MVC架构：
- **视图层（View）**：Swing组件，负责界面展示和用户交互
- **控制器（Controller）**：MainController，接收用户操作，调用算法和IO模块，更新视图
- **模型层（Model）**：图结构、排序结果等数据类

整体界面采用三栏式布局：
```
┌─────────────────────────────────────────────┐
│ 顶部工具栏：文件/计算/导出/布局切换/取消按钮     │
├──────────┬──────────────┬───────────────────┤
│ 输入面板  │  关系图画布   │   结果列表面板     │
│ (输入区)  │  (可视化区)  │  (结果列表/分页)   │
├──────────┴──────────────┴───────────────────┤
│ 底部状态栏：节点数/边数/结果数/状态提示          │
└─────────────────────────────────────────────┘
```

### 2.2 各组件设计

#### 主窗口 MainFrame
- 继承JFrame，默认尺寸1200×800，支持最大化
- 顶部工具栏使用JToolBar放置常用操作按钮
- 中部使用JSplitPane分三栏，各栏宽度可拖拽调整
- 底部放置StatusBar状态栏

#### 输入面板 InputPanel
- 包含JTextArea多行输入区，自动换行
- 底部放置"导入文件""清空""示例数据"按钮
- 点击导入文件弹出JFileChooser选择TXT文件
- 输入内容通过`getInputText()`方法传给控制器

#### 结果面板 ResultPanel
- 使用JList显示排序结果，默认每页20条
- 每条结果格式：`序号. 节点1 -> 节点2 -> ... -> 节点n`
- 单击某条结果触发选中事件，通知控制器高亮对应拓扑序
- 双击结果触发复制事件，将当前序列复制到剪贴板
- 底部分页按钮：首页、上一页、下一页、末页、复制、清空
- 支持通过`getSelectedResultIndex()`获取当前选中的结果序号，用于颜色轮换

#### 关系图画布 GraphPanel（组员C负责，B负责对接）
- 继承JPanel，负责绘制节点、边、高亮效果
- 支持分层布局和环形布局两种切换
- 右下角悬浮按钮：放大、缩小、重置视图、放大查看
- 左上角"放大查看"按钮弹出独立窗口，显示大图
- B对接的核心接口：
  - `setGraph(Graph graph)`：传入要显示的图
  - `setSelectedOrder(List<String> order, int colorIdx)`：高亮指定拓扑序
  - `switchLayout(int mode)`：切换分层/环形布局
  - `resetView()`：重置缩放和平移

#### 状态栏 StatusBar
- 左侧显示统计信息：节点数、边数、结果总数
- 右侧显示状态提示：计算中、完成、取消原因、环提示等
- 提供`setTip(String text)`方法更新提示文本

### 2.3 交互流程设计
1. 用户启动程序，主窗口加载完成，默认显示空白
2. 用户在输入面板粘贴数据或导入文件
3. 用户点击"计算"按钮，MainController启动后台SwingWorker线程
4. 后台线程：调用D的DataParser解析输入 → 构建图 → 调用A的算法枚举拓扑序
5. 计算完成后，EDT线程更新界面：GraphPanel显示图，ResultPanel显示结果列表
6. 用户点击结果列表某行，ResultPanel触发事件，MainController调用GraphPanel的setSelectedOrder高亮该序列
7. 用户可以缩放、平移、切换布局查看关系图
8. 用户点击导出按钮，MainController调用D的FileManager导出结果或图片
9. 计算过程中用户可点击"取消"按钮，中断后台线程

## 三、个人感想与收获

作为小组的项目统筹和任务B的负责人，在这次高级算法课程项目中我收获很多。

从技术层面来说，这是我第一次完整经历一个多人协作的Java项目开发流程。最开始我们五个人先一起开了几次会，确定了整体架构和接口契约，把功能拆成A到E五个模块，每个人负责一块。我负责的是GUI主框架和交互控制，一开始我以为写Swing界面很简单，就是拖一拖组件，但真正做起来才发现，要把不同人写的模块拼到一起、接口对齐、不打架，才是最花时间的。比如最开始和C对接可视化模块的时候，他写的GraphPanel和我写的MainController之间经常对不上，他改了接口我这边没更新，我这边加了功能他那边不知道，来回沟通了好几次才对齐。

和其他组员的对接让我学会了怎么写清晰的接口文档，怎么提前约定好方法名、参数、返回值，而不是写完代码再凑。比如D负责导出，我们之前约定了导出的时候要传"结果是否完整"和"停止原因"两个参数，这样导出的文件才符合任务书要求，不会把截断的结果标成全部。这个过程让我理解了为什么大项目里接口设计这么重要——先把接口定死，大家各自开发，最后再拼，比边写边改效率高太多了。

项目中间也遇到了不少问题，比如最开始合并代码的时候冲突一大堆，尤其是GraphPanel这个文件，C改一点我改一点，每次合并都要解决冲突。还有UI乱码的问题，一开始想用特殊符号做按钮图标，结果Swing在Windows下显示成方框，折腾了半天才发现是字体不支持，最后改成中文"重置"才解决。还有放大查看窗口不跟随布局的bug，找了半天才发现是弹新窗口的时候忘了把当前的布局模式传过去。

团队合作方面，这次五个人分工明确，每个人都有自己负责的模块，但是因为我们用Git分支开发，一开始经常有人推了新代码其他人不知道，导致版本对不上。后来我们约定每天开完会都拉取最新代码，有改动及时在群里说，慢慢就顺畅了。我作为统筹，还要协调大家的进度，提醒谁该做什么，对接的时候两边对齐参数，虽然有点琐碎，但是也锻炼了我组织和沟通的能力。

整体来说，这次项目不仅让我把课堂上学到的拓扑排序、图论知识用到了实际项目里，更重要的是学会了怎么和别人一起协作写代码、怎么设计模块接口、怎么处理版本冲突，这些都是课堂上学不到的工程经验。虽然过程中改了很多bug，合并了很多次代码，但是最后看到整个软件能完整跑起来，从输入关系到枚举所有拓扑序到可视化高亮，那种成就感还是很强的。
